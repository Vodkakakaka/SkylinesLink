# Spec Delta

## Purpose

为不同 AI 客户端提供一致且可验证的城市工具接入体验。核心行为应建立在明确支持的 MCP 协议和传输之上，可选的图像、任务扩展与客户端特性不应成为普通工具调用的隐含前提。

## ADDED Requirements

### Requirement: 两种标准传输具有一致业务语义

系统 SHALL 通过使用官方 TS SDK 的 TypeScript/Node Host 提供 stdio 和本机 Streamable HTTP，在支持的协议版本上复用相同核心工具、参数和结果语义；不支持的协议或能力应明确反馈。stdio 的 stdout 仅承载协议消息，日志使用 stderr。

#### Scenario: 两个客户端调用同一只读工具
- **WHEN** Codex 和 DeepSeek Harness 经支持的 stdio 或 HTTP 协议读取同一游戏观测快照
- **THEN** 其工具参数约束、身份及事实字段一致，不因 AI 品牌改变游戏规则

### Requirement: 订阅安装提供完整运行能力

系统 SHALL 通过一个模组订阅包提供 C# Mod、已构建的 TS Host、Node 运行时与所需许可，提供基础 MCP 能力；已安装游戏和兼容 AI 客户端的玩家不得被要求另装 Host、运行时、桥接插件、开发工具，或编译、执行安装脚本、复制 DLL 才能连接。

#### Scenario: 无开发环境的玩家首次使用
- **WHEN** 玩家订阅并启用模组，在兼容 AI 客户端完成首次连接配置
- **THEN** 客户端可发现并调用基础只读工具，无需从 GitHub 或其他渠道再安装运行组件

### Requirement: 连接配置简明且状态可见

系统 SHALL 提供真实连接命令或地址、必要授权的接入引导及可理解的连接状态，区分未启用模组、无可用城市和连接失败；不能用额外软件安装或未经用户授权修改其他程序配置来替代接入引导。

#### Scenario: 客户端首次添加服务
- **WHEN** 玩家打开模组连接入口
- **THEN** 可获得当前有效的连接信息与最短必要步骤，配置示例不含开发者的本机私有信息

### Requirement: 更新保留稳定入口与匹配组件

系统 SHALL 从已订阅且核验过的文件自动准备稳定连接入口，避免客户端配置依赖市场缓存版本路径；更新时检查 Mod、Host、运行时及契约版本，处理在用文件，失败状态应可见，不通过额外下载或安装脚本弥补缺失文件。

#### Scenario: 市场更新改变缓存目录
- **WHEN** 同一模组更新后文件位于新的平台缓存目录
- **THEN** 玩家既有 MCP 配置仍指向稳定入口，下一次启动使用匹配版本；未能完成切换时明确报告状态，不混合不同发行组件

### Requirement: 内部契约具有单一权威

系统 SHALL 以版本化 schema 统一 C# 与 TS 的内部 HTTP 契约，派生或校验两端类型并验证实际序列化；只传普通值、必要快照和稳定引用，不将游戏规则复制到 Host，也不提供任意反射或代码执行入口。

#### Scenario: 连接到不兼容游戏组件
- **WHEN** Host 与游戏模组的契约或发行版本不匹配
- **THEN** 系统明确拒绝不兼容调用并指出组件状态，不猜测旧字段、静默降级或重放写请求

### Requirement: 本机服务验证访问来源

系统 SHALL 对 Host 的 HTTP 与游戏内部 HTTP 默认仅在本机监听，校验请求 Origin 并验证访问授权；非法来源或无效授权不得执行工具，也不得使本机凭据进入命令行、日志或公开错误内容。

#### Scenario: 网页向本机服务发送非法来源请求
- **WHEN** HTTP 请求包含不被允许的 Origin
- **THEN** 服务拒绝请求且不执行任何游戏操作

### Requirement: 稳定工具契约与完整结果

系统 SHALL 提供稳定工具名称、明确输入约束、符合声明 schema 的结构化结果和可独立理解的文本摘要；分页或截断结果必须明确标记完整性。

#### Scenario: 查询结果超过单次返回规模
- **WHEN** 完整数据不能在一次响应中返回
- **THEN** 系统提供分页或后续查询信息，不把局部结果表述为完整城市事实

### Requirement: 核心操作不强制要求可选扩展

系统 SHALL 通过普通工具调用提供长操作提交及状态查询；MCP Tasks、图像和其他扩展只在客户端支持时使用，缺少扩展不应阻断核心文本与数据操作。

#### Scenario: 客户端不支持 MCP Tasks
- **WHEN** 客户端调用需要较长时间完成的游戏操作且不支持 Tasks 扩展
- **THEN** 系统仍可返回操作标识并通过普通工具提供状态和最终结果

#### Scenario: 客户端不能接收图像
- **WHEN** 当前模型或客户端不能消费图像内容
- **THEN** 系统明确说明图像能力限制，并保留可用的文本及结构化事实，不返回伪造的可视验收结论

### Requirement: 兼容声明对应实测证据

系统发布资料 SHALL 区分目标兼容、协议验证和真实客户端验证，记录版本、传输、已验能力及未验项目；首轮发布以 Codex 和 DeepSeek Harness 的实际接入为必要证据。

#### Scenario: 新客户端尚未实际测试
- **WHEN** 某客户端理论上支持 MCP 但未完成项目测试
- **THEN** 资料将其标为待验证，不宣称该客户端已经完全兼容
