# Spec Delta

## Purpose

为城市读取和操作提供可核验的游戏身份、原生执行及操作状态边界。外部 AI 客户端的连接、超时或重启不应改变游戏规则，也不能让调用者把未知结果理解为执行成功或未执行。

## ADDED Requirements

### Requirement: 操作绑定当前游戏身份

系统 SHALL 在接受游戏操作时核对当前实例、城市和本次加载身份，并在响应中提供可用于核对的身份；没有可用城市或请求身份失效时明确拒绝。

#### Scenario: 加载后旧引用失效
- **WHEN** 客户端携带上一加载周期的城市或对象引用提交操作
- **THEN** 系统拒绝执行，说明身份失效，并要求重新读取当前上下文

### Requirement: 遵循原生建造和资源规则

系统 SHALL 通过适用的原生工具生命周期和校验执行游戏操作，保留正常资金、资格、解锁和碰撞规则；预览通过、提交受理和实际完成必须区分。

#### Scenario: 原生校验拒绝
- **WHEN** 原生工具判定请求不满足建造或资源条件
- **THEN** 系统返回具体拒绝原因，不修改校验条件，也不将请求报告为完成

### Requirement: 写操作串行且结果可查询

系统 SHALL 由 C# 游戏应用层拥有稳定操作标识、可查询状态和唯一执行队列，处理来自多个客户端及 Host 的写请求；TypeScript Host 只投影游戏端状态，客户端取消等待或连接中断不得被报告为原生操作已撤销。

#### Scenario: 提交后客户端超时
- **WHEN** 原生提交已发生但客户端在确认结果前超时
- **THEN** 系统保留原操作标识及已知阶段，允许重连后查询，并明确结果未知时不得直接重放

#### Scenario: 其他客户端尝试重复提交
- **WHEN** 一个仍有效的操作标识被另一个客户端再次提交
- **THEN** 系统返回原操作状态或明确拒绝重复，不再次执行该写操作

#### Scenario: Host 重启后查询操作
- **WHEN** MCP Host 重启但游戏实例和加载周期保持有效
- **THEN** 新 Host 可按原操作标识查询游戏端状态，不因协议进程退出而丢失或重新执行已受理操作

### Requirement: 客户端发现过程无游戏副作用

系统 SHALL 在客户端探测、服务发现和重复连接期间保持游戏状态不变；游戏启动、加载、模拟及存档动作必须由独立的明确操作触发。

#### Scenario: 客户端先探测后启动服务
- **WHEN** 客户端先建立并结束协议探测连接，再建立正式连接
- **THEN** 两次连接均不自动启动游戏、加载存档或重放先前请求

### Requirement: 资源生命周期遵守进程归属

系统 SHALL 随模组加载和释放管理内部 HTTP、发现信息和模组拥有的 HTTP Host，将网络请求与适用游戏线程隔离；使用有界队列及负载控制，监听失败或客户端异常必须可见且不得阻断正常游戏。客户端持有的 stdio Host 由该客户端管理，不得因模组退出误杀其他所有者的进程。

#### Scenario: 模组被释放
- **WHEN** 游戏释放模组或正常退出
- **THEN** 系统关闭内部监听、取消未执行工作并释放自有资源及 HTTP Host；客户端持有的 stdio Host 返回游戏不可用并等待所有者关闭，不要求玩家手工清理孤儿进程

#### Scenario: 客户端结束 stdio 会话
- **WHEN** 客户端关闭对应 Host 的输入通道或终止其会话进程
- **THEN** 该 Host 释放自身资源，不停止其他 Host、游戏或已进入原生提交的操作

#### Scenario: 连接端口不可用
- **WHEN** 本机监听因端口冲突等原因无法建立
- **THEN** 游戏仍可正常使用，模组展示具体连接状态和可恢复办法，不要求关闭安全软件或提升游戏权限

#### Scenario: 请求负载超过处理能力
- **WHEN** 客户端持续发送超过当前处理上限的请求
- **THEN** 系统有界排队或明确拒绝，不无限增长内存，也不在网络线程直接修改游戏对象

### Requirement: 空闲与大型查询保持有界成本

系统 SHALL 在无请求时避免持续全城扫描或完整快照生成，并为大型查询提供明确范围、分页及结果完整性；跨加载周期不得继续返回旧城市对象或缓存事实。

#### Scenario: 模组启用但没有客户端请求
- **WHEN** 玩家保持正常游戏且没有正在执行的 MCP 工作
- **THEN** 模组不持续扫描全城或导出完整状态，其资源成本可由空闲性能测量核对

#### Scenario: 查询范围超出单次处理预算
- **WHEN** 请求所需扫描或响应规模超过当前单次处理上限
- **THEN** 系统按有界工作或分页处理并说明完整性，不无限扩展单帧工作或一次性内存分配
