# Tasks

本清单描述后续实现与验收工作。当前已经交付的目录、公开仓库、调研和规划资料不代表以下产品能力完成；未执行项目保留未勾选状态。以 C# 模组内置 MCP 为起点，必须满足无额外安装和双渠道同版发布。真实游戏写入和正式模组发布不在本轮调研范围内。

## 1. 离线 MCP 与数据契约

- [ ] 1.1 用官方模板构建 C# 9 / net48 模组及普通值契约，固定候选 Core SDK 版本；核查完整依赖并在实际游戏运行时加载，记录冲突或缺口，以此决定保留 SDK 还是验证更小的协议实现。
- [ ] 1.2 实现兼容游戏运行时的嵌入式 Streamable HTTP 与只读示例工具；用协议客户端按声明版本验证初始化/连接规则、发现及结构化结果，记录支持范围，不混用不同版本语义。
- [ ] 1.3 实现有界分页、明确错误和文本摘要；用超量结果、无效参数及不支持能力的样例验证完整性标记与失败语义，并记录工具契约。
- [ ] 1.4 落实 Contracts、Application、GameIntegration、Mcp 与 Mod 的职责及单向依赖；通过构建依赖检查及脱离游戏的协议/应用测试核对边界，记录新增工具的注册与契约步骤。

## 2. 只读游戏连接

- [ ] 2.1 实现本机监听、来源校验与访问授权；验证普通用户权限、非法 Origin、无效授权和端口冲突，不依赖手工 URL ACL 或管理员权限，记录可复现结果。
- [ ] 2.2 实现模组加载/释放、有界网络调度和只读状态读取；验证适用游戏线程、资源释放、异常与负载下的帧时间，记录游戏版本及行为证据。
- [ ] 2.3 实现实例、城市及加载周期身份校验；用世界切换或隔离模拟验证旧引用被拒绝、未加载城市被明确报告，补齐身份字段说明。
- [ ] 2.4 接通内置服务与只读游戏状态；验证重复探测、客户端断开和重连不会启动游戏、加载存档或修改城市，并记录复现步骤。
- [ ] 2.5 建立同环境性能基线与空闲、正常、连续及过载场景；测 CPU/内存增量、分配与 GC、P95/P99 帧耗时和请求延迟、队列及响应规模，据此确定性能预算并纳入回归，验证无空闲全城扫描。

## 3. 操作状态与原生边界

- [ ] 3.1 使用模拟执行器实现单一写队列、稳定操作 ID 和普通工具状态查询；测试多客户端、重复提交、超时及重连时不会重复执行，并记录状态保留范围。
- [ ] 3.2 区分取消等待、尚未执行时取消及原生提交后的状态；用故障注入验证未知结果不会被报告为失败回滚或完成，补充取消与恢复契约。
- [ ] 3.3 在另行明确的游戏写入测试范围内接入原生校验和执行生命周期；验证资金或资格不足时拒绝、正常提交时可追踪实际结果，并记录预览、受理与完成的区别。

## 4. 客户端验收

- [ ] 4.1 在 Codex 与 DeepSeek Harness 分别验证内置 Streamable HTTP、结构化结果、错误和重连；交付包含客户端及协议版本的实测矩阵，保留 stdio 专用及云端客户端的未验状态。
- [ ] 4.2 验证不支持 MCP Tasks 的客户端仍可提交和查询模拟长操作，图像能力不足时仍能获得文本与数据；记录可选能力行为和配置示例，示例不得含真实私有配置。
- [ ] 4.3 提供模组内连接状态、地址和必要授权引导；用首次使用流程验证无效连接、无城市及正常工具发现，无须另装软件、执行脚本或改写他人配置。

## 5. 发行与综合验证

- [ ] 5.1 建立发行清单、依赖许可及源码提交映射；检查包内不含游戏程序集、反编译内容和私人材料，提供实际所需的 MPL 源码获取说明及第三方通知。
- [ ] 5.2 将敏感信息检查用于暂存内容、待推送历史、提交邮箱和发行附件；使用合成敏感样例验证拒绝规则，并人工核查截图及二进制元数据，记录实际提交或制品校验值。
- [ ] 5.3 实现统一版本、提交、更新日志和逐文件校验清单的发布入口，协调 GitHub 草稿与官方 ModPublisher；先用替身验证首次创建、NewVersion 和元数据 Update 的正确分工，并记录运行方法。
- [ ] 5.4 实现两渠道事实核对和部分失败续发；用超时与单边成功场景验证不会重复创建模组或重发成功版本，并记录恢复办法。
- [ ] 5.5 在明确的首发范围内验证官方上传器认证、首次上传与后续新版本；核对 ModId、平台版本和公开状态，不把命令退出成功等同于两端可用。
- [ ] 5.6 在仅有游戏与目标 AI 客户端的 Windows 环境通过 Paradox Mods 订阅并启用模组，完成只读调用、更新与退出；记录无需额外 Host、运行时或桥接工具的实际证据。
- [ ] 5.7 对同一发行候选复核协议、真实客户端、游戏环境及平台条款证据；发布说明分别列明构建、连接、订阅与两渠道发布状态，完成 OpenSpec 严格校验。
- [ ] 5.8 在同版候选上执行已建立的性能场景和预算比较，记录环境、基线及退化情况；公开报告脱敏，性能未验或超预算不得标记为已达标。
