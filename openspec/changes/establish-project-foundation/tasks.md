# Tasks

本清单描述 C# Mod + TypeScript/Node Host 的后续实现与验收。现有目录、公开仓库、工具安装与规划文档不代表产品能力完成。必须满足单订阅安装、双传输及双渠道同版发布；真实游戏写入和正式模组发布不在本轮调研范围内。

## 1. 工具链、契约与离线 MCP

- [ ] 1.1 依据工具基线初始化组件目录和项目配置，固定 Node、pnpm、.NET SDK 及稳定依赖；通过 pnpm 安装项目 TypeScript，生成唯一 pnpm 锁文件，验证类型检查、构建与可复现安装，并提供开发命令。
- [ ] 1.2 建立版本化内部 schema、身份、普通值响应与错误契约，生成或校验 C# / TS 类型；以两端序列化和不匹配版本样例验证一致性，记录兼容边界。
- [ ] 1.3 用官方 TS SDK 实现共用工具处理器的 stdio 与 Streamable HTTP Host，先连接模拟 GameClient；验证声明协议的发现、结果、错误和 stdout 纯协议输出，记录协议支持范围。
- [ ] 1.4 落实 Contracts、GameApplication、GameIntegration、GameClient、Mcp 与模组组装职责；通过构建依赖和离线测试核对单向边界，记录工具注册、分页与完整性约定。

## 2. C# 只读接口与两组件连接

- [ ] 2.1 用官方模板构建并加载 C# 9 / net48 模组，建立内部 HTTP 和适用游戏线程调度；验证普通用户权限、依赖、加载与释放，不要求 URL ACL 或管理员权限，记录游戏版本。
- [ ] 2.2 为内部接口与 Host HTTP 实现本机绑定、Origin 校验、授权及受控发现；测试非法来源、错误凭据、端口冲突和组件版本不匹配，确认错误与日志不泄露凭据。
- [ ] 2.3 实现实例、城市与加载周期校验、只读查询范围和有界分页；验证无城市、旧引用和过载拒绝，确保网络线程不直接访问游戏对象，补齐接口说明。
- [ ] 2.4 接通 TS GameClient 与 C# 只读状态；验证客户端探测、重连和 Host 重启不启动游戏、不加载存档、不修改城市，记录复现证据。

## 3. 进程、入口与操作生命周期

- [ ] 3.1 实现客户端拥有的 stdio Host 和模组按需管理的 HTTP Host；测试多客户端、关闭输入、游戏退出与 Host 崩溃，确认只释放自有资源且游戏继续正常使用。
- [ ] 3.2 从已订阅且核验过的文件准备稳定连接入口与版本化运行文件；测试更新时文件占用、失败恢复、重复启动与版本不匹配，确认无需额外下载或人工复制，记录保留及清理规则。
- [ ] 3.3 在 C# 应用层用模拟执行器实现唯一写队列、稳定操作 ID 与查询；测试跨 Host 重复提交、超时和重连不重复执行，明确 Host 不拥有独立操作账及游戏重载后的保留范围。
- [ ] 3.4 区分取消等待、取消未执行工作和原生提交；用故障注入验证未知状态不会被报告为已回滚或已完成，补充恢复契约。
- [ ] 3.5 在另行明确的游戏写入测试范围接入原生生命周期；验证资格、资金和碰撞拒绝以及实际提交结果，记录预览、受理与完成的区别。

## 4. 客户端与性能验收

- [ ] 4.1 在 Codex 和 DeepSeek Harness 分别验证 stdio、Streamable HTTP、结构化结果、错误和重连；交付包含客户端、SDK 和协议版本的矩阵，未测试客户端保持待验状态。
- [ ] 4.2 验证不支持 Tasks 的客户端可提交和查询模拟长操作，图像能力不足时仍有文本与数据；提供不含私人配置的接入示例。
- [ ] 4.3 提供模组连接状态、稳定命令或地址及必要授权引导；验证首次配置、无城市和无效连接，不改写其他软件配置或要求安装工具。
- [ ] 4.4 建立相同环境无模组、仅 Mod、单 Host、多 Host、空闲、连续请求与过载基线；统计全部进程与分项 CPU/内存、GC、游戏线程及 P95/P99 延迟、事件循环、传输量和队列，据此确定回归预算并确认无空闲全城扫描。

## 5. 打包与同步发布

- [ ] 5.1 建立统一版本和发行清单，随包提供官方可移植 Node、构建后的 Host、Mod、许可证及源码获取说明；检查来源、校验值及组件版本，不包含游戏程序集、开发环境或私人材料。
- [ ] 5.2 对暂存内容、待推送历史、提交邮箱和发行附件执行脱敏检查；用合成敏感样例验证规则，人工复核截图与二进制元数据，记录实际提交或制品校验值。
- [ ] 5.3 实现统一版本、源码提交、更新日志和内容清单的发布入口，协调 GitHub 草稿与官方 ModPublisher；用替身验证 Publish、NewVersion 和元数据 Update 的分工并记录运行方法。
- [ ] 5.4 实现两渠道事实查询和部分失败续发；用超时、单边成功场景验证不重复创建条目、不重发成功版本、不覆盖同版不同内容，提供恢复说明。
- [ ] 5.5 在明确的首发范围核实携带 Node 与 Host 的平台规则，验证官方认证、首次上传和 NewVersion；记录 ModId、平台接受的文件及实际可见状态，不把上传器收集文件视为平台批准。
- [ ] 5.6 在仅有游戏与目标 AI 客户端的 Windows 环境完成 Paradox Mods 订阅、启用、两种传输只读调用、更新与退出；确认使用随包运行时，稳定入口有效且无额外安装。
- [ ] 5.7 对同一发行候选复核协议、真实客户端、平台条款、双渠道内容一致性及性能预算；公开记录脱敏并分别列明构建、订阅、连接、性能和发布状态，完成 OpenSpec 严格校验。
