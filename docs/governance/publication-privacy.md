# 公开材料与脱敏规则

所有上传材料均按最小必要范围发布，并在上传前检查敏感信息。范围包括源码、文档、Git 历史与提交元数据、Issue/PR、截图、日志、构建报告、调试符号和发行附件；不能仅检查当前工作区。

公开内容只说明SkylinesLink自身的设计、功能、使用与维护。内部工作资料、原始调研、比较记录及讨论不上传，也不通过文档链接、注释、提交说明或开发分支历史夹带。必要的第三方依赖许可/版权与实际集成对象的正常技术名称保留。不能只删除最新文件或添加ignore规则便声称历史已经排除；发布须核实际将上传的提交集合和载荷。

## 处理方式

- 凭据、令牌、密码、私钥、会话标识和认证头不上传；示例只使用明确的占位符，不保留真实值的前后片段。
- 个人邮箱、私人账号、设备名、绝对安装路径、内网地址、私人仓库地址和业务数据，按用途移除或替换为通用示例。项目公开账号、官方仓库地址和必要的版权署名保留。
- 配置采用不含真实值的示例；路径使用相对路径或环境变量。公开的诊断记录保留错误类型、必要版本和复现步骤，去除个人及环境识别信息。
- 日志、截图和二进制不能直接套用源码文本检查结果。需分别检查画面内容、文件元数据、嵌入路径、配置、符号和实际压缩包清单；未完成检查的材料不上传。
- 私人存档、旧资产包、原始研究材料、游戏程序集和反编译源码不进入公共仓库或发行包。适用的许可证和第三方版权通知须完整保留，不能借脱敏删除依法应保留的信息。

## 提交与发布检查

1. 明确本次上传文件清单；本机助手配置和研究记录使用仓库私有忽略规则隔离。
2. 检查实际暂存内容、将推送的提交历史、作者和提交者邮箱。使用维护者的 GitHub 隐私邮箱，避免暴露私人邮箱。
3. 结合敏感信息扫描与人工审阅，检查文档链接、配置、路径、标识及附件内容。扫描无命中不等于绝对没有泄露。
4. 对发行包检查实际内容和元数据；记录所审提交或制品校验值，上传后核对发布对象一致。

若凭据曾经外泄，先撤销或轮换该凭据，再处理公开材料和历史；仅删除最新版本中的值不能消除泄露。当前规则是发布约束，自动化扫描和制品检查工具尚待实现，不能将文档存在表述为自动防护已经生效。
